# 設計上の合意

## 対象と出力

- 自分用の Discord Bot。
- 新規メッセージに直接添付された PDF を対象にする。本文のリンクと編集による添付追加は対象外。
- Bot による投稿は対象外とする。Webhook による自動投稿も対象外とする。
- Bot が閲覧できるチャンネルすべてを対象とする。Bot 独自の対象チャンネル設定は作らず、範囲は Discord 側の閲覧権限で調整する。
- Bot 独自の入力 PDF サイズ上限は設けず、Discord に添付された PDF を対象にする。
- PDF の1ページ目を PNG に変換する。縦横比を保ち、長辺は最大1200 px。
- 生成した PNG が Discord の送信上限に収まらない場合だけ、縮小して再生成する。送信可能なサイズにできなければ、そのファイルは通知せずスキップする。
- 元メッセージへの返信は1件。成功分を先に返信し、再試行で成功した分は同じ返信に追加する。
- 一時的な失敗は再試行するが、元メッセージの投稿から10分を過ぎたら送信・添付追加を開始しない。
- 通信切断などで送信結果が不明になり、確認しても送信済みか判断できない場合は、重複を避けて再送せず終了する。明確に一時的な送信失敗と判断できる場合は期限内で再試行する。
- 失敗・期限切れの Discord 通知は不要。ログに記録してよい。全件失敗なら返信しない。
- 元メッセージが削除されても、送信済みのプレビュー返信は削除しない。
- まだプレビュー返信を送っていない段階で元メッセージが削除された場合は、処理を中止する。通常の投稿として PNG だけを送ることはしない。

## 実行環境

- Workers Paid を利用する。ローカルのライブラリ動作検証は一旦 OK として設計を進める。
- Gateway の Durable Object は受信と接続維持を担当し、プレビュー生成は独立した Worker に任せる。
- `@hyzyla/pdfium` と `@cf-wasm/png` を使用する。
- 2026-10-24 に本番へデプロイした。実際の投稿での送受信とピークメモリの確認は残っている。検証の詳細は [技術検証](../spike/README.md) を参照。
